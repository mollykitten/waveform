# Waveform — идея проекта

Минималистичный, клавиатурный SoundCloud-клиент для десктопа. Нативный, тёмный,
тихий. Flutter → macOS, Windows, Linux из одной кодовой базы.

## Зачем это вообще

У SoundCloud до сих пор нет нормального десктоп-клиента. Официального нет
вовсе; неофициальные — либо мёртвые, либо Electron-обёртки над сайтом, либо
выглядят как курсовая. Люди слушают SoundCloud во вкладке браузера, которая
теряется среди сорока других, не ловит медиа-клавиши и забывает позицию при
перезагрузке.

Из этого вытекает всё остальное:

- **Премиальный look and feel.** Раз рынок пустой, планка — не «работает», а
  «хочется открывать». Плотная типографика, ритм отступов, spring-анимации,
  frosted chrome, ambient-подложка из обложки. Ближе к каноничному SoundCloud,
  но темнее и спокойнее.
- **Кроссплатформенность как условие, а не бонус.** Десктоп-пользователи
  SoundCloud размазаны по трём ОС, ни одна не оправдывает отдельный нативный
  клиент. Поэтому Flutter: один код, один дизайн, три платформы, настоящие
  нативные окна и медиа-интеграция ОС (Control Center, SMTC, MPRIS).
- **Клавиатура первична.** Space играет, ⌘K находит что угодно, стрелки
  перематывают, ⇧+стрелки листают треки. Весь экран — один граф
  `Shortcuts` + `Actions`. Полный паритет с клавишами веб-SoundCloud плюс
  палитра команд в стиле Raycast.
- **Только настоящие данные.** Никаких подставных секций, фейковых счётчиков и
  моков в боевой сборке. Если данных нет — честное пустое состояние.
- **Честность про основу.** Клиент неофициальный, живёт на `api-v2`
  (ToS-серая зона). Это пишем прямо в README.

## Дизайн-контракт в двух словах

Тёмная тема по умолчанию. bg `#0A0A0A`, surface `#111111`, акцент — SoundCloud
orange `#FF5500` только на активных элементах, lime `#C6FF00` — второй акцент для меток и маркеров.
Inter для текста, JetBrains Mono для всех цифр, тайм-кодов и технических
меток. Радиусы 3px, границы 0.5px. Обложка 160×160 слева, waveform во всю
ширину справа, метаданные моно-шрифтом снизу. Полный контракт, палитра и
токены — в `CLAUDE.md`.

## Что уже работает (v0.3.0)

- Реальный `api-v2`: стрим, лента, библиотека, поиск, страницы трека, артиста,
  плейлиста; `client_id` скрейпится на лету.
- Логин через собственный WebView; токен хранится в sandboxed-директории
  приложения, пароль приложение не видит.
- Лайки и репосты пишутся по-настоящему: запросы выполняются внутри
  невидимого WebView приложения, потому что DataDome режет «голый» HTTP-клиент
  по TLS-отпечатку.
- Аудио: HLS через `just_audio`, двухдвижковая схема с gapless и crossfade
  0–6 с, progressive-фолбэк.
- Медиа-клавиши и now-playing через `audio_service` — пока только macOS.
- ⌘K-палитра, глобальные шорткаты, right-click меню, очередь с drag-and-drop,
  сворачиваемый плеер, ambient-подложка.
- Last.fm-скробблинг (опционально), локальная статистика прослушиваний.
- «Моя волна»: реальные SoundCloud-кандидаты, ChatGPT/custom-provider подключение,
  одноразовое связанное согласие и непрерывное пополнение очереди. Локальные
  структурные векторы используют ограниченный related-граф и факты прослушивания;
  это не нейронные аудиоэмбеддинги. Live OAuth/подписка/Keychain и музыкальное
  качество ещё требуют проверки; реализация не означает опубликованный релиз.
- CI (analyze + test) на каждый push. Релизный пайплайн по тегу `v*` на три
  ОС написан (DMG с подписью и нотаризацией при наличии Apple-секретов,
  Windows zip, Linux tar.gz), но ни один релиз через него ещё не прошёл:
  опубликованных релизов нет, прогоны падали.

## Идеи и бэклог

Текущий статус и этапы — в [docs/roadmap.md](docs/roadmap.md),
канонический контракт — в `CLAUDE.md`, «Путь развития».

Крупное:

- **Backend и аудиоэмбеддинги** — запланированы: сначала проверка музыкального
  качества и разрешённых источников, затем API, PostgreSQL vector index,
  фоновые versioned embeddings и гибридное ранжирование. Sync только по отдельному
  opt-in, с изоляцией аккаунтов, удалением и локальным fallback. Подписка ChatGPT
  в приложении не финансирует backend inference. Этапы — в roadmap.
- **Light theme** + следование системному appearance.
- **Lyrics view** на странице трека.
- **Heatmap прослушиваний** по часам недели (`played_at` из play-history,
  CustomPainter 7×24).
- **Mini-window mode**: компактное always-on-top окно «только плеер».
- **Полный VoiceOver-проход** (accessibility-аудит); reduced-motion уже реализован.
- **Drag треков между плейлистами** (веб-SC почти не даёт).

Платформенное:

- **Windows-логин**: WebView2 лагает на тяжёлой странице SoundCloud, сейчас
  основной путь — вставка `oauth_token` вручную. Нужен либо лёгкий
  signin-flow, либо другой webview-бэкенд. Google-попап в логин-WebView
  тоже блокируется.
- **Deep-link `waveform://`** на Windows (реестр) и Linux (`.desktop` с
  `x-scheme-handler`); на macOS уже зарегистрирован.
- **Windows code-signing** (EV-сертификат): zip без подписи, SmartScreen
  ругается.
- **Проверка нотаризации** на чистой macOS после релиза.
- **AirPlay / выбор аудиовыхода на macOS** — реализовано: per-app выбор
  CoreAudio-устройства для AVPlayer и системный `AVRoutePickerView` для
  AirPlay. Детали реализации и ограничения — в [docs/audio-output.md](docs/audio-output.md).
  Непрерывность live-воспроизведения на физическом AirPlay-приёмнике ещё
  ожидает проверки на оборудовании.

Когда откроют API:

- **Official OAuth 2.1 + PKCE** (регистрация приложений закрыта годами).
- **Запись play-history и лайки комментариев** — `api-v2` отдаёт 404,
  ревайвить через тот же `_send`-паттерн, если появятся.

Уже реализовано: shuffle всей коллекции лайков с пагинацией `track_likes` и
кнопкой над сеткой likes; shuffle плейлиста тоже доступен.

## Чего не делаем

- Не скрейпим cookies из чужих браузеров — это поведение инфостилера, его
  ловят антивирусы. Антибот-cookie берём только из собственного WebView.
- Не добавляем ничего для абьюза сервиса: массового скрейпинга, обхода банов.
  Исключение по решению владельца (2026-10): воспроизведение GO+ через
  Widevine-расшифровку (`scdrm`) для собственного аккаунта пользователя.
  Профиль устройства пользователь добывает и кладёт сам — в репозиторий и
  релизные сборки он не попадает, раздавать его нельзя.
- Не кладём мок-данные в боевую сборку; моки только под
  `--dart-define=MOCK=true` и в тестах.
- Не делаем web3: кошельки, NFT-метки, WalletConnect — снято, к проекту не относится.
- Не хардкодим и не коммитим секреты: `client_id` скрейпится, токены лежат в
  файле приложения, Last.fm-ключи приходят через `--dart-define`.
